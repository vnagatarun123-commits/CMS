# PuraLocal CMS — Starter Bundle (START HERE)

This folder is the planning + rules + docs scaffold for the PuraLocal CMS. It contains **no
application code** — that gets generated by Claude Code in VS Code, following these files.

## What's in here

```
puralocal-cms-starter/
├── CLAUDE.md                  # Project rules — Claude Code reads this automatically. Keep at repo root.
├── Docs/                      # Engineering docs scaffold (49 files). Real content + "Needs Implementation" stubs.
│   ├── README.md              # How the docs work
│   └── Coverage-Report.md     # What's documented vs pending
└── prompts/                   # Prompts you paste/reference in Claude Code
    ├── phase-0-frontend-mock-prompt.md   # ← USE THIS FIRST
    ├── phased-roadmap-prompts.md         # Phases 1–8 (after Phase 0 is done)
    ├── docs-generation-prompt.md         # Run at the END of each phase to update /Docs
    └── archive/
        └── phase-0-foundation-prompt-OLD-do-not-use.md   # superseded — ignore
```

## How to use it (in order)

1. **Use this whole folder as your project root** (or copy `CLAUDE.md`, `Docs/`, and `prompts/` into your repo root).
2. `git init && git add . && git commit -m "Project rules + docs scaffold"`.
3. Open the folder in VS Code, start Claude Code, and send:

   > Read `prompts/phase-0-frontend-mock-prompt.md` and execute it. Follow `CLAUDE.md` as the project rules. Show me your plan, the skills/MCPs/plugins you recommend, and the file list before writing any code.

4. Review its plan. Hold the line on the **seam rule** (no fake data inside components) and the **UI/domain/data separation**.
5. When Phase 0 passes its tests, run `prompts/docs-generation-prompt.md` (Mode B) to update `/Docs`, then start Phase 1 from `prompts/phased-roadmap-prompts.md`.

## Key decisions already baked in

- **Stack:** Next.js + Supabase (Auth + Postgres + Storage) + Prisma (schema/migrations) + Tailwind/shadcn.
- **Approach:** frontend-first against an in-memory mock, behind a seam; swap in Supabase later without rewriting UI.
- **Tenancy:** `organizationId` everywhere + a data-layer guard from day one; Supabase RLS added when the real DB lands. Multi-tenant UI (onboarding, branding, domains, org switch) is the FINAL phase.
- **You only need Node + pnpm to start** (the mock phase needs no database). Supabase is set up later at the swap slice.

## Prerequisites before you open Claude Code
- Node.js (LTS) and **pnpm** installed. That's it for the mock phase.
